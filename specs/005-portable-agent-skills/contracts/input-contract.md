# Contract — 입력 계약과 초기 인터뷰

스튜디오 폼과 단독 실행이 **같은 항목**을 채운다. 차이는 값이 채워져 있느냐뿐이어야 한다 (FR-053).

## 라벨 블록

백엔드가 프롬프트에 붙이는 형식. **값이 있는 라벨만** 붙인다.

```
[사용자 작업 요청]
{prompt}

[구축 의도]
{intent}

[골든 퀘스천]
1. {q1}
2. {q2}

[연결 데이터소스]
1. {name} (스키마: {schemas})

[대상 스키마]
{schema_name}

[검토 피드백]
1. 질문: {question}
   이전 판정: {verdict}
   이전 상태: {status}
   기존 답변: {answer}
   사용자 피드백: {feedback}
```

### 백엔드가 하면 안 되는 것

| 금지 | 지금 어디에 있는가 | 어디로 가는가 |
|---|---|---|
| "아래 데이터소스의 테이블과 조회조건에 근거하여 온톨로지를 설계하세요" | `_compose_build_prompt` | 스킬 본문 |
| "카탈로그 탐색은 datasource_list / datasource_describe 도구를 사용하세요" | 동일 | 스킬 본문 (참조 자료) |
| "아래 질문들에 답할 수 있는 온톨로지 스키마와 그래프를 구축하세요" | 동일 | 스킬 본문 |
| "이를 해결하도록 온톨로지를 개선하세요" | 동일 | 스킬 본문 |
| `[완료 기준]` 블록 전체 | 동일 | 스킬 본문의 "완료 기준" 절 |

**백엔드가 넘기는 것은 값이지 지시문이 아니다** (FR-015).

## 스킬이 지켜야 하는 인터뷰 규칙

### 필수 항목

| 항목 | 라벨 | 없으면 |
|---|---|---|
| 구축 의도 | `[구축 의도]` | 묻는다 |
| 골든 퀘스천 | `[골든 퀘스천]` | 묻는다 |
| 대상 소스 | `[연결 데이터소스]` 또는 업로드 파일 | 묻는다 (둘 다 없을 때) |

`[사용자 작업 요청]` 안에 사실상 담겨 있으면 **있는 것으로 본다.** 라벨의 존재가 아니라 정보의
존재로 판정한다 — "설비별 가동률을 알고 싶다" 는 골든 퀘스천이다.

### 절차

1. 받은 것을 점검한다
2. **전부 있으면**: 이해한 바를 요약해 보이고 곧바로 진행한다. 응답을 요구하지 않는다 (FR-052)
3. **빠진 것이 있으면**: 빠진 것만 묻고 **턴을 끝낸다.** 도구를 호출하며 기다리지 않는다 (FR-054)
4. 답이 오면 다시 점검한다. 되묻기는 **최대 2회** (FR-055)
5. 상한에 닿으면 확보한 것으로 진행하되 **가정한 내용을 명시**한다
6. 전략 선택지가 여럿이면(문서+데이터소스가 모두 있는 경우 등) 선택지와 근거를 제시하고 고르게
   한다. 조용히 하나를 고르지 않는다 (FR-056)

### 금지

| 금지 | 근거 |
|---|---|
| 이미 받은 항목을 다시 묻는다 | FR-051 |
| 다 갖춰졌는데 확인 응답을 요구한다 | FR-052 / SC-013 |
| 빠졌는데 임의로 지어내고 진행한다 | FR-051 / SC-012 |
| 골든 퀘스천 문장을 다듬는다 | FR-057 / SC-015 — 리포트에 원문 그대로 나와야 한다 |
| 호출 경로에 따라 다르게 군다 | FR-053 / SC-014 |

## 판정 테이블 (테스트가 강제)

| 입력 상태 | 기대 동작 | 검증 |
|---|---|---|
| 의도·골든 퀘스천·소스 모두 있음 | 되묻기 0회, 요약 후 진행 | SC-013 |
| 아무것도 없음 | 3항목을 묻고 턴 종료 | SC-012 |
| 의도만 있음 | 골든 퀘스천·소스만 묻는다. 의도를 다시 묻지 않음 | FR-051 |
| 문서 + 데이터소스 둘 다 있음 | 전략 선택지를 제시 | FR-056 |
| 스튜디오 폼 완비 | 단독 실행의 "모두 있음" 과 동일 | SC-014 |
| 스튜디오 폼에서 의도 비움 | 단독 실행의 "의도 없음" 과 동일 | SC-014 |
