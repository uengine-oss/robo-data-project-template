# Phase 1 — 데이터 모델

이 기능에는 데이터베이스 스키마가 없다. 여기서 "모델" 은 **파일 구조와 그 위에서 오가는 값**이다.
런타임 상태는 하나도 늘지 않는다 — 그것이 이 설계의 목표다.

---

## 1. SkillPackage (스킬 패키지)

폴더 하나. 저장소에서는 `ontology-studio/skills/<name>/` 에 있다.

| 필드 | 출처 | 규칙 |
|---|---|---|
| `name` | 폴더 이름 | 1~64자, 소문자·숫자·하이픈. `-` 로 시작/끝 금지, `--` 금지. **프론트매터 `name` 과 일치해야 한다** |
| `metadata` | `SKILL.md` 프론트매터 | 아래 SkillMetadata |
| `body` | `SKILL.md` 프론트매터 이후 전체 | 지시문. 이것이 시스템 프롬프트가 된다 |
| `references` | `references/*.md` | 0개 이상. 본문이 상대 경로로 가리킨다 |
| `plugin_manifest` | `.claude-plugin/plugin.json` | 배포용. 런타임은 읽지 않는다 |
| `mcp_config` | `.mcp.json` | 배포용. 런타임은 읽지 않는다 |

**검증 실패는 예외다** (FR-014). 조용한 건너뛰기가 없다. 실패 시 메시지는 **어느 폴더의 무엇이**
잘못됐는지 지목한다.

### SkillMetadata (프론트매터)

agentskills.io 규격을 따른다. deepagents 가 인식하는 필드와 동일하게 유지한다(R1).

| 필드 | 필수 | 규칙 | 이 프로젝트에서의 쓰임 |
|---|---|---|---|
| `name` | ✓ | 위 `name` 규칙 | 폴더명과 교차 검증 |
| `description` | ✓ | 1~1024자 | **단독 실행의 유일한 발견 경로.** 무엇을 하는지 + 언제 쓰는지를 함께 쓴다 |
| `version` | ✓ (이 프로젝트) | semver | FR-007. 표준에서는 선택이지만 여기서는 필수 |
| `license` | – | | |
| `compatibility` | – | ≤500자 | "Ontology Studio 백엔드 필요" 같은 전제를 여기에 |
| `allowed-tools` | – | 공백 구분 | 권한 경계의 기계 판독 형태 (FR-006 의 산문 서술과 병행) |
| `metadata` | – | 자유 키-값 | |

## 2. SkillBody (본문) 의 필수 구성

FR-003·FR-004·FR-005·FR-006·FR-050 을 만족하려면 본문에 아래 절이 **반드시** 있어야 한다.
[skill-package.md](contracts/skill-package.md) 가 이를 계약으로 고정한다.

| 절 | 담는 것 | 근거 FR |
|---|---|---|
| 언제 쓰는가 | 이 스킬이 맡는 작업의 범위 | FR-002 |
| 전제 | 필요한 도구와 그 출처(agent-bridge MCP), 없을 때의 행동 | FR-004 |
| 권한 경계 | 읽기 전용인지 쓰기 가능한지 | FR-006 |
| 입력 | 받는 라벨 목록과 없을 때의 인터뷰 규칙 | FR-050~058 |
| 작업 경로 | 입력·출력 위치를 환경 무관하게 | FR-005 |
| 워크플로우 | 단계 순서와 **어느 참조 자료를 언제 읽는지** | FR-040, FR-041 |
| 완료 기준 | 무엇이 되면 끝인가 (기존 `[완료 기준]` 이 여기로) | FR-015 |

## 3. ReferenceDoc (참조 자료)

| 필드 | 규칙 |
|---|---|
| 경로 | 스킬 폴더 기준 상대 경로. 본문에서 그대로 쓴다 |
| 참조 시점 | 본문의 워크플로우가 **언제 읽을지 지목**한다 (FR-041) |
| 내용 | 기존 본문에서 **옮겨온 것**. 다시 쓰지 않는다 (FR-043) |

### 분할 계획 (출발점)

`ontology_build.md` (현재 수백 줄) → 본문 + 6개:

| 참조 자료 | 현재 본문의 어느 부분 | 언제 읽는가 |
|---|---|---|
| `ingestion-patterns.md` | 4가지 인제스천 패턴 A~D, D-1 | Phase 1 시작, 소스 성격 판정 시 |
| `strategies.md` | 전략 선택표, `build_strategy_recommend`, 역바인딩, 인과발견 | Phase 1 0단계 |
| `datasource-binding.md` | 바인딩 절차, behavior 작성, SQL 템플릿 규칙, 파라미터 타입 | 가상 클래스를 만들 때 |
| `parser-rules.md` | content 수집 2-pass, 노드 속성 규칙, 구조 파싱, 자체 검증 | 파서를 쓰기 직전 |
| `source-types.md` | PDF/Excel/Shapefile/Markdown/PPTX 파싱 가이드 | 파일 타입을 확인한 뒤 |
| `validation.md` | Phase 3 검증 절차, 검색 힌트 파일, 최종 리포트 형식 | Phase 3 |

`ontology_answer.md` → 본문 + 1개:

| 참조 자료 | 내용 | 언제 |
|---|---|---|
| `search-strategy.md` | 0~4단계 검색 전략, 가상 클래스 발견, 도구 우선순위 | 첫 조회 전 |

본문에 남는 것: 역할, 전제, 권한 경계, 입력 계약, 작업 경로, 단계 순서, 핵심 규칙, 완료 기준.

## 4. BuildInput (입력 계약)

스튜디오 폼과 단독 실행 인터뷰가 **같은 항목**을 채운다. 형식은 라벨 블록이다(R6).

| 라벨 | 필수 | 값 | 없을 때 |
|---|---|---|---|
| `[사용자 작업 요청]` | ✓ | 사용자가 친 문장 | 성립 불가 |
| `[구축 의도]` | ✓ | 무엇을 위한 온톨로지인가 | **묻는다** |
| `[골든 퀘스천]` | ✓ | 답해야 할 질문 목록 | **묻는다** |
| `[대상 소스]` | ✓ | 업로드 문서 / 연결 데이터소스 (둘 중 최소 하나) | **묻는다** |
| `[전략]` | – | 003 의 전략 선택 | 선택지가 여럿이면 **제시하고 고르게 한다** (FR-056) |
| `[대상 스키마]` | – | 기존 스키마에 추가할 때 | 새로 만든다 |
| `[검토 피드백]` | – | 이전 리포트에 대한 사용자 판정 | 없음으로 진행 |

**질의 응답 스킬의 입력은 질문 그 자체**다. 인터뷰가 없다(스펙 Assumptions).

### 인터뷰 상태 전이

```
받은 입력 점검
   ├── 전부 있음 ──→ 이해한 바 요약 ──→ 작업 시작        (되묻기 0회, SC-013)
   └── 빠짐 있음 ──→ 빠진 것만 질문 + 턴 종료
                        │
                        ├── 답 도착 ──→ 다시 점검 (최대 2회)
                        └── 상한 도달 ──→ 가정 명시 ──→ 작업 시작   (FR-055)
```

전이 규칙:

- 요약은 **응답을 요구하지 않는다.** 요약 후 곧바로 다음 단계로 간다 (FR-052)
- 이미 받은 항목을 다시 묻지 않는다 (FR-051)
- 질문할 때는 **도구를 호출하지 않고 턴을 끝낸다** (FR-054, 헤드리스 제약)
- 확정된 값은 설계·검증 내내 기준으로 남는다 (FR-058)
- 골든 퀘스천은 **글자 그대로** 보존되어 리포트에 다시 나온다 (FR-057, SC-015)

## 5. EnvironmentBinding (환경 바인딩)

런타임이 주입하는 **값 블록**. 지시문이 아니다 (FR-015).

| 키 | 내장(샌드박스) | cliagents(호스트) | 단독 설치 |
|---|---|---|---|
| 스킬 폴더 | `<workdir>/.skills/<name>/` | `<LOCAL_SANDBOX_ROOT>/.claude/skills/<name>/` | 에이전트가 자기 것을 안다 |
| 업로드 | `<workdir>/uploads/` | `<LOCAL_SANDBOX_ROOT>/uploads/` | 사용자가 정한다 |
| 출력 | `<workdir>/output/` | `<LOCAL_SANDBOX_ROOT>/output/` | 사용자가 정한다 |

단독 설치에서는 이 블록이 없다. 본문의 "작업 경로" 절이 **없을 때 어떻게 정하는지**를 말해야 한다
— 그것이 FR-003(스튜디오 코드 없이 성립) 의 요구다.

004 의 `_host_workspace_note()` 는 이 블록으로 흡수되고 사라진다.

## 6. DistributionArtifacts (배포 산출물)

런타임이 읽지 않는다. 사용자의 에이전트가 읽는다. 상세 스키마는
[distribution.md](contracts/distribution.md).

| 산출물 | 위치 | 역할 |
|---|---|---|
| `plugin.json` | `skills/<name>/.claude-plugin/` | 이 폴더를 플러그인으로 만든다 |
| `.mcp.json` | `skills/<name>/` | 해당 모드의 agent-bridge 엔드포인트 등록 |
| `marketplace.json` | `ontology-studio/.claude-plugin/` | 두 플러그인의 카탈로그 |

## 불변식

구현이 지켜야 하고 테스트가 강제해야 하는 것들.

1. **본문은 한 곳에만 있다.** 저장소 어디에도 같은 지시문 문장의 두 번째 사본이 없다 (SC-003)
2. **폴더 이름 = 프론트매터 name.** 어긋나면 로드 실패
3. **레지스트리가 유일한 진입점.** 두 백엔드 모두 다른 경로로 스킬을 읽지 않는다
4. **`answer` 스킬의 권한 경계가 쓰기를 포함하지 않는다.** 본문·`allowed-tools`·`.mcp.json` 셋이
   같은 말을 한다
5. **참조 자료는 옮겨진 것이다.** 분할 전후로 지시문 총합이 같다 (SC-010)
6. **레지스트리는 langchain 을 import 하지 않는다** (R9, SC-004)
